# 모의실험(simulation) 설계

작성일: 2026-10-09 · 결과: `docs/README_29_32_SIMULATION.md`

## 0. 목적

실제 자료 분석에서 얻은 결론 중, 이 설계(13 pH × 3 phone × 5 light, phone × pH마다 strip 1개)의
구조적 특성에 기대고 있는 부분을 모의실험으로 검증한다.

| 검증 대상 | 실제 자료의 근거 | 모의실험이 보여줄 것 |
|---|---|---|
| **S1. 분석 단위와 검정 타당성** | Background pH: strip 단위 p = 0.57, 이미지 단위 p = 0.0001 | 이미지 단위 순열검정은 1종 오류가 부풀고, strip 단위 검정은 명목 수준(5%)을 지킨다 |
| **S2. GAM의 폰별 곡선 식별** | 폰별 곡선이 strip 분산의 39–66%를 설명. LOSO에서 ΔE −1.1 | 폰별 곡선이 **없을 때** GAM이 "있다"고 잘못 판단하지 않고, **있을 때**는 찾아낸다. strip 랜덤효과를 빼면 오판이 늘어난다 |
| **S3. 경계 pH 거동** | RCS가 pH 1/13에서 유의하게 악화 (knot 3: +7.9 ΔE) | 경계에 이상이 없는 매끄러운 참값에서도 RCS가 실패하는지 → 실패가 방법 때문인지 데이터 때문인지 구분 |

## 1. 자료 생성 모형 (공통)

실제 Contrast 자료의 추정값으로 맞춘다 (script 26, tp k = 10).

```
y[ph, phone, light] = f(ph)                       공통 pH 곡선 (M0/M1 적합값)
                    + δ_phone                      폰별 상수
                    + A · g_phone(ph)              폰별 곡선 모양 (M2 적합값의 shape 성분)
                    + light + phone:light          조명 효과 (실제 추정값)
                    + u_strip ~ N(0, σ_s²)         매끄럽지 않은 strip 편차
                    + e ~ N(0, σ_e²)               이미지 잡음
```

실제 자료 기준값 (Contrast, 채널별):

| 채널 | σ_e (이미지 잡음) | σ_s (M2 기준 strip 편차) | 폰별 곡선 모양의 폭 |
|---|---|---|---|
| L* | 0.66 | 2.30 | 6–11 |
| a* | 0.54 | 1.97 | 2–17 |
| b* | 0.82 | 3.38 | 4–14 |

- `A`는 폰별 곡선의 강도이다. A = 1이 실제 추정 크기이고, A = 0이면 폰별 곡선이 없는 귀무가설이다.
- 이미지 잡음과 strip 편차는 정규분포로 생성한다.

## 2. S1: 분석 단위와 순열검정

**시나리오**

| 요인 | 수준 |
|---|---|
| pH 주효과 크기 τ (pH 효과 SD / 이미지 잡음 SD) | 0 (귀무), 0.5, 1, 2 (실제 Background ≈ 0.2–0.8) |
| σ_s / σ_e | 0, 0.5, 1, 2, 4, 6 (실제 Background ≈ 0–1, Contrast ≈ 3.5–4 (M2 기준), 4.5–6 (M1 기준)) |
| 반응변수 | Lab 3채널 (ASCA와 같은 다변량 pseudo-F) |

**비교할 검정**
- strip 단위 제한 순열 (script 25 주 분석)
- 이미지 단위 비제한 순열 (일반적인 ASCA 관례)

**지표:** 기각률. 귀무가설 아래에서는 1종 오류, 대립가설 아래에서는 검정력.

**반복 수:** 시나리오당 1,000개 자료 × 순열 999회. Monte Carlo 표준오차는 5% 기준으로 약 0.7%p이다.

**추가 시나리오 (pH × phone 해석용):** 폰별 곡선이 없고(A = 0) strip 편차만 있을 때,
Freedman–Lane pH × phone 검정의 기각률을 본다.
→ 100%에 가깝게 나오면 "ASCA의 pH × phone 유의성 ≠ 폰 효과"임을 수치로 보여줄 수 있다.
이것이 GAM 단계로 넘어가는 근거가 된다.

**가설:** σ_s > 0이면 이미지 단위 검정의 1종 오류가 크게 부풀고(σ_s/σ_e가 클수록 심해짐), strip 단위 검정은 약 5%를 유지한다.

## 3. S2: GAM 폰별 곡선의 식별

**시나리오**

| 요인 | 수준 |
|---|---|
| A (폰별 곡선 강도) | 0, 0.25, 0.5, 1 |
| σ_s (strip 편차) | 실제값의 0.5배, 1배, 2배 |
| 채널 | a* (주), L*·b*는 A = 0, 1에서만 |

총 12개 셀(a* 기준).

**적합 모형:** script 26과 같은 M1, M2 (tp k = 10, REML), 그리고 비교용으로 strip 랜덤효과를 뺀 M2(naive).

**지표**

| 지표 | 계산 | 확인할 것 |
|---|---|---|
| 폰별 곡선 검정 기각률 | M2의 by-smooth 근사 p < 0.05 (폰 2개 중 하나 이상, Holm 보정 포함/미포함) | A = 0에서 1종 오류, A > 0에서 검정력 |
| naive 모형 기각률 | strip 랜덤효과 없는 M2 | 랜덤효과를 빼면 1종 오류가 부푸는지 |
| strip 분산 감소율 | 1 − σ²_s(M2) / σ²_s(M1) | A = 0에서 0 근처인지, A에 따라 증가하는지 |
| 곡선 추정 정확도 | 참 g_phone과 추정 shape 곡선의 RMSE, 95% 동시 신뢰구간 포함률 | 신뢰구간이 제대로 작동하는지 |

**반복 수:** 셀당 500개 자료. 자료당 GAM 적합 3회.

**LOSO 부분 (계산량이 큼):** A = 0과 A = 1, σ_s 실제값 두 셀만 200회 반복한다.
M2 − M1 ΔE 차이의 분포를 보고, A = 0일 때 "가짜 개선"이 생기지 않는지 확인한다.

## 4. S3: 경계 pH

- 참값: A = 1의 매끄러운 곡선. 경계에서 특별한 이상을 넣지 않는다.
- GAM M2와 RCS(knot 3, 4, 5; ridge 포함 여부)의 LOSO를 pH 1/13과 2–12로 나눠 비교한다.
- 경계에서 RCS만 실패하면 "실제 자료의 경계 실패는 방법 특성"이라는 주장을 뒷받침한다.
- 데이터셋: S2의 LOSO용 데이터셋(A = 0, 1 각 200개)을 그대로 사용한다. RCS 모형은 script 19의 코드를 그대로 불러와 쓴다.

## 5. 구현

| 파일 | 내용 | 실행 시간 (Mac, 실측) |
|---|---|---|
| `scripts/29_sim_permutation_unit.py` | S1 (numpy, 순열을 묶음으로 계산) | 약 32분 (코어 1개) |
| `scripts/30_sim_gam_identification.R` | S2 식별 + LOSO용 데이터셋 생성 (mgcv) | 약 9분 (소켓 워커 6개) |

| `scripts/31_sim_loso_rcs.py` | S3: RCS (script 19 코드) | 약 15분 (워커 6개) |
| `scripts/32_summarize_simulation.py` | S2·S3 요약과 그림 | 1분 이내 |
| `run_simulation.ps1` | 전체 실행 | 약 1.5시간 |

- 모든 시나리오에 고정 seed를 쓰고, 자료 생성 모수는 실제 적합 결과(`outputs/gam_curves/`)에서 읽는다.
- macOS에서는 fork 방식 병렬화(`mclapply`)가 Accelerate BLAS와 충돌해 소켓 클러스터(`parLapply`)를 사용한다.
- 결과: `outputs/simulation/` (시나리오별 기각률, Monte Carlo 표준오차, 그림)

## 6. 논문에서의 위치

- Methods에 "2.x Simulation study" 소절을 추가한다(설계, 생성 모형, 지표).
- Results에 S1 표 1개, S2 그림 1–2개를 넣는다.
- Discussion의 "분석 단위의 중요성"과 "GAM이 식별하는 것의 의미"를 모의실험 결과로 뒷받침한다.
